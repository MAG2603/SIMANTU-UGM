=================================================================
1. RINGKASAN EKSEKUTIF
=================================================================
SIMANTU adalah aplikasi desktop untuk manajemen dan otomasi pengumuman
bilingual (Bahasa Indonesia dan Bahasa Inggris) berbasis Text-to-Speech
(TTS). Sistem ini menggabungkan frontend React, backend Express, dan shell
Electron dalam satu produk operasional.

Tujuan utama SIMANTU:
1. Mempermudah operator membuat, menyimpan, dan memutar template pengumuman.
2. Menjalankan pengumuman terjadwal secara otomatis.
3. Menjaga kualitas pengucapan bilingual dengan aturan ejaan dan tag bahasa.
4. Menyediakan antarmuka modern yang responsif untuk layar kecil hingga besar.

Karakter produk:
- Mode operasi: desktop app (Electron).
- Bahasa UI: Indonesia (utama), dengan dukungan teks EN pada konten.
- Model penyimpanan data saat ini: file JSON lokal.
- Integrasi TTS: Microsoft Edge TTS + ffmpeg transcode.

=================================================================
2. LATAR BELAKANG DAN TUJUAN SISTEM
=================================================================
Kebutuhan operasional pengumuman di lingkungan institusi pendidikan menuntut:
1. Proses cepat dan konsisten.
2. Jadwal terotomasi tanpa intervensi terus-menerus.
3. Dukungan pengucapan bilingual yang jelas.
4. Kontrol penuh operator saat terjadi benturan antara pengumuman manual
   dan jadwal otomatis.

SIMANTU dibangun untuk memenuhi kebutuhan di atas melalui:
- Template library (CRUD).
- Scheduler harian dengan opsi recurring.
- Mesin playback yang mendukung antrean.
- Penanganan konflik jadwal vs manual play dengan modal keputusan.
- Notifikasi visual dan desktop.

=================================================================
3. RUANG LINGKUP PRODUK
=================================================================
Ruang lingkup yang dicakup sistem:
1. Pengelolaan template pengumuman:
   - Buat, baca, ubah, hapus template.
   - Simpan favorit.
   - Simpan pilihan suara per bahasa.
2. Pemutaran pengumuman:
   - Manual play dari dashboard.
   - Dukungan antrean jika sedang ada playback aktif.
3. Penjadwalan:
   - Buat jadwal pemutaran pada jam tertentu.
   - Opsi recurring (harian).
   - Claim schedule untuk mencegah duplikasi eksekusi.
4. Konfigurasi audio:
   - Pilih output device.
   - Atur volume.
   - Aturan pengucapan (spelling rules).
   - Bell pembuka/penutup kustom.
5. Pengemasan desktop:
   - Build renderer dan server.
   - Packaging installer Windows/macOS/Linux (sesuai script).

Hal yang belum dicakup penuh:
- Multi-user dengan autentikasi/otorisasi.
- Sinkronisasi cloud/database terpusat.
- Audit log tingkat enterprise.

5. ARSITEKTUR SISTEM
=================================================================
5.1 Gambaran Arsitektur Tingkat Tinggi
1. UI React berjalan dalam BrowserWindow Electron.
2. UI memanggil REST API internal pada /api/*.
3. Express server memproses API dan mengakses storage JSON.
4. Untuk TTS, server memanggil msedge-tts, lalu mentranscode audio ke
   MPEG1 Layer3 agar kompatibel dengan decodeAudioData.
5. Audio diputar di client menggunakan Web Audio API.

5.2 Pola Komunikasi
- Frontend -> Backend: HTTP fetch JSON + endpoint binary audio.
- Frontend -> Electron Main: IPC via electronAPI (preload).
- Electron Main -> Frontend: event window-hidden (untuk stop audio saat hide).
- Electron Main -> Frontend: event app-update-status (untuk notifikasi pembaruan).
- Electron updater -> GitHub Releases: cek versi dan unduh paket pembaruan.

5.3 Mode Runtime
- Development:
  - dev:server menjalankan Express + Vite middleware.
  - dev:electron menunggu http://localhost:5000 lalu membuka Electron.
- Production:
  - Electron menjalankan server ter-embed dari bundle dist-electron/server.js,
    lalu membuka URL localhost internal.

8. DOKUMENTASI API
=================================================================
Base URL (dev): http://localhost:5000

8.1 Announcements
1. GET /api/announcements
   - Deskripsi: ambil semua template.
   - Response 200: Announcement[]

2. POST /api/announcements
   - Deskripsi: buat template baru.
   - Body:
     {
       "title": "...",
       "contentId": "...",
       "contentEn": "...",
       "voice": "Pria/Pria",
       "isFavorite": false
     }
   - Response 201: Announcement
   - Response 400: { message, field? }

3. PUT /api/announcements/:id
   - Deskripsi: update template.
   - Body: partial insert schema.
   - Response 200: Announcement
   - Response 404: { message: "Announcement not found" }

4. DELETE /api/announcements/:id
   - Deskripsi: hapus template.
   - Response 204
   - Response 404

8.2 Schedules
1. GET /api/schedules
   - Deskripsi: ambil semua jadwal.

2. POST /api/schedules
   - Deskripsi: buat jadwal.
   - Body:
     {
       "announcementId": 1,
       "playTime": "2026-03-14T08:00:00.000Z",
       "status": "Waiting",
       "recurring": true
     }

3. PUT /api/schedules/:id
   - Deskripsi: update jadwal.
   - Body: partial insert schedule schema.

4. POST /api/schedules/:id/claim
   - Deskripsi: klaim jadwal untuk mencegah race condition.
   - Sukses jika status awal Waiting.
   - Response 409 jika sudah diklaim/tidak Waiting.

5. DELETE /api/schedules/:id
   - Deskripsi: hapus jadwal.

8.3 TTS
1. POST /api/tts
   - Body:
     {
       "text": "isi teks",
       "voice": "id-ID-ArdiNeural"
     }
   - Response 200: binary audio/mpeg

2. GET /api/tts/voices
   - Response: daftar preset suara.

8.4 Status
1. GET /api/status
   - Response 200: { "connected": true }

9. LOGIKA BISNIS INTI
=================================================================
9.1 Alur Manual Playback
1. Operator menulis teks ID/EN di dashboard.
2. Operator pilih voice ID dan voice EN.
3. Saat tombol Play ditekan:
   - Jika sedang Preparing: request ditolak dengan toast.
   - Jika sedang Playing: konten masuk antrean.
   - Jika idle: lanjut proses TTS + playback.
4. Bell pembuka/penutup diputar jika fitur bell aktif.

9.2 Alur Scheduler Otomatis
1. Sistem cek schedule periodik (30 detik).
2. Kondisi eksekusi:
   - schedulerEnabled = true
   - tidak sedang playing/preparing
   - antrean kosong
3. Schedule due diklaim lewat endpoint claim.
4. Jika berhasil klaim dan pengumuman valid:
   - playAudio dipanggil.
   - Setelah selesai:
     - recurring => geser ke hari berikutnya.
     - non-recurring => status Done.

9.3 Grace Period dan Robustness
- Jadwal overdue lebih dari 5 menit dianggap stale, ditandai Done.
- Jadwal yang announcement-nya sudah tidak ada ditandai Done.
- Klaim mencegah double-play akibat overlap interval/tick.

9.4 Konflik Manual vs Jadwal
Saat operator menekan Play dan ada jadwal prioritas (imminent/starting),
sistem menampilkan modal dengan 3 opsi:
1. Lanjutkan manual + batalkan occurrence jadwal bentrok.
2. Lanjutkan manual tanpa membatalkan jadwal (jadwal ditahan/defer).
3. Batalkan pengumuman manual (jadwal tetap prioritas).

Jika opsi defer dipilih:
- Setelah playback manual selesai, dialog konfirmasi muncul:
  - Putar jadwal sekarang.
  - Lewati jadwal ini.

9.5 Antrean Pengumuman
- Jika playback aktif dan operator menekan Play lagi, item masuk queue.
- Queue diputar otomatis berurutan setelah playback aktif selesai.
- Stop/Reset mengosongkan queue.

=================================================================
10. PIPELINE AUDIO DAN TTS
=================================================================
10.1 Ringkasan Pipeline
Input teks -> preprocessing -> request TTS -> audio mp3 dari server ->
decodeAudioData -> play via AudioBufferSourceNode -> output speaker.

10.2 Preprocessing Teks
1. Apply spelling rules (custom + default).
2. Dukungan tag bahasa inline:
   - [en: phrase]
   - [id: phrase]
3. Parser tag:
   - case-insensitive
   - toleran spasi
   - toleran penutup ] atau }
4. Pembersihan marker dangling jika format tidak rapih.

10.3 Default Spelling Rules
Rule bawaan (aktif default):
- UGM -> U G M
- L1 -> L Satu
- L5 -> L Lima
- ETD -> E T D
- WIB -> Waktu Indonesia Barat

10.4 Fallback Spelling di Server
Server tetap menerapkan fallback untuk menjaga kualitas pengucapan jika
aturan sisi client tidak terpasang.

10.5 Segmentasi dan Voice Switching
- Root language ditentukan dari voice ID.
- Segmen [en: ] di teks ID bisa menggunakan EN voice (atau multilingual voice).
- Segmen [id: ] di teks EN bisa menggunakan ID voice (atau multilingual voice).

10.6 Kompatibilitas Codec
msedge-tts menghasilkan MPEG2 Layer3 24kHz yang tidak selalu kompatibel
langsung dengan decodeAudioData Chromium.
Solusi:
- Server mentranscode audio ke MPEG1 Layer3 44.1kHz via ffmpeg.

17A. FITUR AUTO-UPDATE (PEMBARUAN OTOMATIS)
=================================================================
17A.1 Gambaran Umum
SIMANTU mendukung pembaruan aplikasi over-the-air (OTA) menggunakan
electron-updater yang terhubung ke GitHub Releases. Saat versi baru
dirilis, aplikasi yang sudah terpasang di komputer pengguna akan
memberitahu operator dan dapat memperbarui dirinya sendiri.

17A.2 Cara Kerja (Sisi Pengguna)
1. Saat aplikasi pertama kali dijalankan, pengecekan update berjalan
   otomatis setelah 5 detik.
2. Jika ada versi baru, notifikasi native muncul dan toast tampil di UI.
3. Unduhan berjalan di latar belakang secara otomatis.
4. Setelah unduhan selesai, notifikasi "siap instal" muncul.
5. Operator dapat mengklik tombol "Pasang & Restart" di halaman Settings,
   atau menunggu sampai aplikasi ditutup dan dibuka kembali.
6. Cek manual juga tersedia via menu tray atau tombol di halaman Settings.

17A.3 Cara Kerja (Sisi Teknis)
- electron-updater membaca app-update.yml yang ter-embed di package.
- Feed URL: GitHub Releases pada repository yang dikonfigurasi.
- IPC channels:
  app-update-check  (handle)  — trigger cek manual dari renderer.
  app-update-install (handle) — trigger quitAndInstall dari renderer.
  app-update-status  (send)   — broadcast status ke renderer.
- Status events: checking | available | downloading | downloaded |
  not-available | error | disabled.
- Auto-update hanya aktif pada aplikasi yang sudah di-install
  (app.isPackaged = true). Pada mode dev menampilkan status "disabled".

17A.4 Setup GitHub Repository untuk Rilis
Prasyarat sekali-pakai sebelum rilis pertama:

1. Buat repository GitHub (public atau private).
2. Buat Personal Access Token (PAT) dengan scope:
   - public_repo  (untuk repository publik)
   - repo         (untuk repository private)
3. Pastikan package.json build.publish dikonfigurasi:
   {
     "provider": "github",
     "owner": "MAG2603",
     "repo":  "SIMANTU-UGM"
   }
4. Opsional (hanya jika ingin override ke repo lain saat testing):
   set SIMANTU_GITHUB_OWNER=<username-atau-org>
   set SIMANTU_GITHUB_REPO=<nama-repo>
   set GH_TOKEN=<personal-access-token>

17A.5 Prosedur Rilis Versi Baru (Developer)
Langkah-langkah setiap kali ingin merilis pembaruan:

1. Perbarui versi di package.json:
   "version": "X.Y.Z"

2. Pastikan GH_TOKEN sudah di-set. Env owner/repo hanya diperlukan jika override feed (lihat 17A.4).

3. Jalankan:
   npm run release:win

   Script ini menjalankan secara berurutan:
   a. prebuild:images   — buat ikon .ico dari sumber.
   b. build            — build renderer + server bundle.
   c. electron-builder --win --publish always
                       — paket installer + upload ke GitHub Releases.

4. GitHub Releases secara otomatis akan berisi:
   - SIMANTU-Setup-X.Y.Z.exe   (installer NSIS)
   - SIMANTU-X.Y.Z-full.nupkg  (paket update differensial)
   - latest.yml                 (feed versi untuk auto-updater)

5. Aplikasi yang sudah terpasang di komputer pengguna akan mendeteksi
   rilis ini pada pengecekan berikutnya.

17A.6 Konfigurasi NSIS Installer
- oneClick: false  (installer tampilkan wizard)
- perMachine: false  (instalasi per-user, tidak butuh admin)
- allowToChangeInstallationDirectory: true
- requestedExecutionLevel: asInvoker

17A.7 Catatan Penting
- Pada mode dev (npm run dev), updater otomatis dinonaktifkan.
- AppUserModelId di main.cjs HARUS sama dengan appId di package.json
  agar nama aplikasi muncul benar di bar notifikasi Windows.
  Nilai saat ini: com.ugm.simantu
- Jika GitHub repo bersifat private, GH_TOKEN juga diperlukan di
  mesin pengguna (tidak praktis). Direkomendasikan menggunakan
  repository publik untuk distribusi pembaruan.
